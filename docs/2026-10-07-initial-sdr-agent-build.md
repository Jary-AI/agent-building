# Initial SDR Agent Build

**Date:** 2026-10-07
**Context:** Convert the SDR role from a general-purpose tool operator into a campaign-by-campaign operating agent.

## What was learned

1. A campaign must be the unit of execution. A channel or a tool is not a campaign.
2. The Portal GTM Program is the commercial contract: audience, problem, offer, sales play, enablement, control and result standard.
3. The agent must separate live evidence, defined strategy and candidate ideas.
4. The useful result is a named next decision, not reach, sends or signups alone.
5. Human approval is required at the moment before sending, publishing, CRM syncing or changing a lifecycle state.
6. Tool readiness is not campaign readiness. Connected Gmail, Brevo or Metricool cannot compensate for an unclear offer or weak proof.

## First operating portfolio

The current SDR portfolio is recorded in `Jary-AI/jary-sdr/docs/campaign-portfolio-and-execution-plan-2026-10-07.md`. The first execution candidate is Partner Fit Clinic, with Jary Portal Continuity as the awareness entry point.

## Build pattern

```text
campaign hypothesis
  -> target cohort and exclusion rules
  -> operating trigger and offer
  -> approved proof and channel plan
  -> draft assets and QA
  -> human approval
  -> smallest live test
  -> outcome readback
  -> learning record and next campaign decision
```

## Agent boundary

The agent may research, classify, draft, QA, reconcile read-only data and recommend a next action. It may not send, publish, sync CRM, change pricing, promise results or widen access without an explicit human decision.
